# Apple 人机界面指南

将本地沉淀的 Apple 设计知识应用到用户的界面。本地参考文件包含可直接使用的指导，官方链接用于溯源和更新。普通设计任务可以全程在本地完成，无需先打开这些链接。

## 明确设计上下文

确定用户任务、目标平台、框架、最低系统版本，以及需要交付的是建议、审查、设计还是实现。先从对话和项目推断，再询问缺失的信息。

在仓库中工作时，阅读仓库指引、设计系统和相关功能的不变量。找到当前界面及其共享组件。评估用户要求的改动时，保留产品既有的语言、图标体系和交互约定。

区分构建 SDK 与最低部署版本。新 SDK 带来的外观变化，与采用新 API，是两个不同的决策。不熟悉的 API 应对照已安装的 SDK 或当前文档核实；兼容旧版本所需的行为放在项目的共享组件层。

## 阅读相关的本地知识

只加载与任务相关的文件和平台章节。来源链接说明指导来自哪里，不代表需要逐一抓取所有来源。

## 按用户要求的工作方式应用知识

- **建议或设计：** 推荐能帮助用户完成任务的交互和组件，解释收益与重要取舍，补充理解流程所需的状态。
- **审查：** 检查提供的设计或实现。有源码时，追踪行为的负责对象和调用方。按用户影响报告具体问题：位置、触发条件、后果，以及最小而有效的修正。区分实际观察到的行为与从代码推断的风险，也区分 Apple 指导、项目规则和自己的审美判断。
- **实现：** 通过已有组件和负责对象完成已授权的改动。优先使用原生控件及共享封装。说明自定义控件要解决的具体需求，并一并实现交互状态和无障碍行为。集中管理共享外观与兼容性决策。

本地内容是对 Apple 建议的整理，不是合规认证标准。应用相关判断依据即可，无需让每个任务都经历完整审计或数值评分。

## 何时查阅外部来源

以下情况需要查阅具体的官方来源：

- 用户要求当前官方指导、核实来源，或本地未覆盖的官方示例。
- 决策依赖某个系统版本、新 API、弃用情况、测试版行为或精确参数，而本地内容和已安装的 SDK 无法确认。
- 任务需要未覆盖的主题、视觉示例、可下载素材，或需要解决证据冲突。

仅在这些情况或用户明确要求更新 skill 时，使用[来源查询与维护](references/apple-resources_zh-CN.md)。设计判断优先参考当前 HIG，API 行为参考框架文档或已安装的 SDK。核实日期较早，本身并不意味着每项稳定的设计判断都需要重新联网查询。

对于 Apple HIG 和 API 文章网址，按来源查询参考中的命令运行附带的[读取器](scripts/read-apple-docs.mjs)，然后阅读保存的 Markdown。脚本路径相对于本 `SKILL.md` 所在目录解析，不是项目目录。读取器需要 Node.js 22.20+ 和网络，本地知识只需要文件读取能力。

查询失败时，继续完成本地知识能够支持的决策，并指出尚未确认的具体结论。可以引用本地记录的来源网址，但不要声称刚刚完成了在线核实。日常使用不代表要重写 skill。

## 用证据收尾

说明做出了什么决策或改动，以及验证了什么。来源有助于解释问题时，引用本地指导或其记录的官方来源。构建成功证明代码可以编译；实际外观和交互需要各自的证据。遵守仓库关于构建、用户手动检查和已授权 UI 自动化的规则，指出仍需进行的针对性手动检查。
