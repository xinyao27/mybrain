# 组件选择

本地指导，核实日期：2026-09-16。根据组件支持的任务和交互选择它。以下示例说明如何应用指导，不是强制的产品布局。

## 导航

**标签栏（Tab bar）：** 用于同级的顶层目的地。切换时保留各目的地的导航状态。某个区域没有内容时，也应保持入口稳定；解释空状态，不要让入口消失。使用简短、明确的标签。导出等操作应放在控件或菜单中，不应作为目的地标签。

来源：[Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)。

**侧边栏（Sidebar）：** 当信息层级和可用空间适合常驻导航列表时使用。将相关目的地分组，保持标签简洁。优先采用浅层结构；更深的结构可以在侧边栏与详情之间增加内容列表。适用时，允许用户通过熟悉的控件显示或隐藏侧边栏，并保持入口容易发现。自定义能力可以帮助用户更快到达各自常用的目的地。

来源：[Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)。

## 工具栏与菜单

**工具栏（Toolbar）：** 展示针对当前内容的实用操作，以及标题、返回、搜索等帮助定位和导航的控件。对相关操作分组，保持顺序可预测。宽度缩小时区分项目优先级，并采用平台内置的溢出行为。仅当多一层入口有价值时，才将低频操作放入“更多”菜单。让原生控件和系统工具栏负责背景及受支持的自定义行为。

来源：[Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)。

**菜单（Menu）：** 展示与当前上下文相关的命令或选项。使用描述结果的简短标签，并在适用时显示选中状态或对应快捷键。通过原生禁用状态保留暂不可用命令的可辨识性。包含不可用命令的菜单仍可以打开，方便用户发现这些能力。上下文菜单提供便捷的情境操作，应用菜单组织更完整的命令集合。

来源：[Menus](https://developer.apple.com/design/human-interface-guidelines/menus)。

## 按钮与值控件

操作使用按钮；修改值或选择项时，使用专门的开关、选择器或分段控件。通过标签、图标、语义角色和样式明确操作结果。

适度使用突出样式来区分最可能的操作。一组同类选项中，应优先增强样式，而不是随意放大某个按钮。为输入方式保留足够间距。自定义按钮需要即时的按下状态，以及禁用、焦点、键盘和无障碍行为；原生控件已提供其中大部分交互约定。

来源：[Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)。

## 窗口、sheet 与 popover

| 用户需要                     | 初始选择       | 主要影响                     |
| ---------------------------- | -------------- | ---------------------------- |
| 在已有内容旁处理独立项目     | 窗口（Window） | 支持并行工作和独立放置。     |
| 完成与父界面相关的短任务     | Sheet          | 明确任务与父界面的关系。     |
| 临时查看或调整少量上下文细节 | Popover        | 保持锚定在触发它的元素附近。 |

**窗口：** 支持调整大小，保留原生窗口控件和边框。当并行工作或保留上下文对用户有益时，打开额外窗口。不要为普通导航不断增加窗口。持续使用的编辑器可能适合独立窗口，短暂配置步骤则未必需要。

来源：[Windows](https://developer.apple.com/design/human-interface-guidelines/windows)。

**Sheet：** 保持任务聚焦，明确关闭的含义。Cancel 放弃未提交的改动；Done 完成任务。Back 用于流程内返回，而不是关闭呈现。Mac、watchOS、tvOS 和 visionOS 的 sheet 是模态的；iOS 和 iPadOS 还支持非模态 sheet。避免从主界面层层叠加 sheet。对于耗时较长的编辑，或需要一边使用父界面一边操作的工具，可以考虑平台提供的窗口、面板、分栏视图或非模态呈现。

来源：[Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)。

**Popover：** 内容应紧凑、相关，并锚定在来源附近。避免遮挡完成任务所需的信息。一次显示一个，在适用时支持熟悉的点击外部关闭行为。非模态 popover 自动关闭时应保留用户工作；只有明确取消才丢弃。支持多选的 popover 应保持打开，直到用户完成选择。对于不能让用户错过的警告，使用更合适的呈现方式。

来源：[Popovers](https://developer.apple.com/design/human-interface-guidelines/popovers)。

## 将选择应用到功能

明确入口、选中的上下文、操作、可见结果，以及关闭或恢复路径。只检查功能实际存在的状态：设置面板可能需要选择和禁用状态；导出流程还需要进度、失败和完成状态。根据具体任务解释自定义行为，而不是默认自定义界面一定更好。
