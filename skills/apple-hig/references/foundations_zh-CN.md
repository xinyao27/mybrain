# 设计基础

根据 Apple 来源整理的本地指导，核实日期：2026-09-16。直接使用这些判断依据；来源链接用于归属说明和后续更新。

## 设计原则

| 原则                   | 如何应用到界面                                                         |
| ---------------------- | ---------------------------------------------------------------------- |
| 目的（Purpose）        | 明确用户想得到的结果，优先做好能切实帮助达成结果的功能。               |
| 自主（Agency）         | 让进入、导航、取消和恢复都容易理解。用户改变操作方向时，保留已有工作。 |
| 责任（Responsibility） | 解释实际的数据用途，在相关情境下仅请求必要权限，并保护用户的工作。     |
| 熟悉（Familiarity）    | 复用用户已学会的控件和隐喻，让同类操作及其位置保持一致。               |
| 灵活（Flexibility）    | 考虑不同设备、输入方式、能力，以及有用的个性化选择。                   |
| 简洁（Simplicity）     | 让重要选项容易发现。可见控件变少，不一定意味着步骤更少或困惑更少。     |
| 打磨（Craft）          | 处理各个状态下的细节：布局、反馈、性能、语言和过渡。                   |
| 愉悦（Delight）        | 选择适合产品的感受，在不妨碍任务的前提下强化它。                       |

用这些原则解释取舍，不必在审查中逐一写出八个章节。每项改进建议都应将具体的界面选择与用户结果联系起来。

来源：[Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)。

## 信息层级与排版

结合位置、分组、字重、字号和颜色建立层级。优先使用系统文字样式与已有项目设计变量；系统字体已针对平台调校。避免多套字体相互竞争，也避免小字号使用过细、难以辨认的字重。

用户放大文字后，标题和正文仍应容易区分。让内容重新排布，保留完成任务所需的信息，而不是通过缩小文字解决溢出。平台支持时，让有意义的图标随标签一起缩放。较长的翻译也应保留可用的控件与清晰的阅读顺序。

来源：[Typography](https://developer.apple.com/design/human-interface-guidelines/typography)。

## 颜色

为标签、背景、分隔线、选择和状态使用语义颜色。系统颜色会适配外观与无障碍偏好。自定义颜色需要为支持的外观及增强对比度提供合适的变体。

保持每种颜色含义一致。如果一种颜色在某处表示可交互，那么使用同色的装饰文字可能让人误以为它也可操作。用标签或形状强化状态。结合实际背景评估颜色，包括图像和半透明表面；单独查看色块不能证明内容可读。

来源：[Color](https://developer.apple.com/design/human-interface-guidelines/color)。

## 文案

导航入口按内容命名，操作按结果命名。使用熟悉的词语和稳定的术语。用产品既有的表达风格说明错误及有帮助的下一步，并根据情境的严肃程度调整语气。

同一流程阶段使用一致的标签。让开始、继续、完成和取消容易区分。大小写遵循组件与项目的语言约定。保留本地化基础设施，每种语言都要自然表达。

实际应用：导出失败需要清楚的解释和可用的恢复操作；空资料库需要提供添加第一项内容的途径。技术子系统名称若不能帮助用户决定下一步，就不要放进文案。

来源：[Writing](https://developer.apple.com/design/human-interface-guidelines/writing)。

## 动效与反馈

用动效解释状态变化、表达关系或响应输入。反馈应简短，并与操作存在明确因果关系。进入和退出时应保持一致的空间感。

原生组件已为高频交互提供轻量反馈。新增自定义动效所消耗的注意力和时间应有明确价值。尽可能允许用户中断或取消；重复出现的过渡不应阻挡下一步操作。启用“减弱动态效果”后，反馈仍需容易理解，且不要仅靠动画传递信息。

根据具体交互选择时长和弹簧行为。本指南不规定统一的 Apple 动画时长、回弹或弹簧预设。

来源：[Motion](https://developer.apple.com/design/human-interface-guidelines/motion)。
