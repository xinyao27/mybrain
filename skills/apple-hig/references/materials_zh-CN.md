# 材质与 Liquid Glass

本地整理，核实日期：2026-09-16。无需抓取来源页面即可使用这些设计规则。API 签名、可用版本和新系统行为属于独立的实现问题。

## 选择层级与材质

| 表面                                   | 初始处理方式                                        |
| -------------------------------------- | --------------------------------------------------- |
| 位于内容上方的导航和功能控件           | 使用标准组件的系统外观；受支持时采用 Liquid Glass。 |
| 内容背景与内容内部的分组               | 使用语义背景或适合该内容的标准材质。                |
| 位于多变文字或图像上方的自定义悬浮控件 | 确实需要自定义玻璃效果时，采用 regular 玻璃。       |
| 位于丰富照片或视频上方的小控件         | 检查对比度和背景处理后，考虑 clear 玻璃。           |

Liquid Glass 将导航和控件与下方内容区分开来。如果内容卡片或列表普遍采用玻璃，会削弱这种层级关系。系统控件在操作过程中可以短暂出现玻璃元素，例如滑块的交互部分；这不意味着周围内容也应成为玻璃表面。

Regular 玻璃会调整背景以保持可读性，适合作为文字较多或背景不可预测时的起点。Clear 玻璃优先保留媒体的可见性。明亮媒体可能需要压暗；足够暗的内容，或已自行提供压暗处理的系统播放控件，则未必需要。结合实际前景与背景一起判断。

来源：[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)。

## 通过组件采用外观

从已有原生控件或共享封装开始。使用较新的 SDK 重新构建，可能无需替换交互就能更新外观。对于受支持的按钮，优先使用系统按钮样式，不要手动再包一层玻璃效果。

检查遮蔽系统效果的自定义填充、视觉效果背景和覆盖层。已经拥有表面的控件或呈现，不应再被额外玻璃表面包裹。保留系统间距与安全区域行为，避免圆角控件、标题栏和内容相互挤压。内容滚动时，保留工具栏的滚动边缘处理，不要用固定绘制的背景将其遮住。

来源：[Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)。

## 几何、强调与适配

嵌套形状应保持关联：结合圆角半径和内边距评估，不要在每层重复同一个半径。密集的 Mac 控件可以保留紧凑的圆角矩形，突出且空间充裕的操作则使用更大的形状。平台控件本身已体现这些区别。

有选择地着色，用来标记重要操作。检查自定义表面在移动内容上方，以及活跃和非活跃状态下的表现。遵循“降低透明度”“增强对比度”和“减弱动态效果”；标准材质行为已适配这些偏好，自定义效果则需要单独验证。

来源：[Get to know the new design system — WWDC25](https://developer.apple.com/videos/play/wwdc2025/356/)、[Meet Liquid Glass — WWDC25](https://developer.apple.com/videos/play/wwdc2025/219/)。

## 实现与审查决策

项目支持旧系统时，保留其原生基线体验，将受支持的新外观放在共享组件边界内。这是实现策略，不是提高最低部署版本的理由。

怀疑存在玻璃问题时，先定位每个表面由谁绘制、内容属于哪一层。审查应指出具体的干扰背景、重复效果、不可读状态或几何问题。构建可以验证 API 使用；不同背景及无障碍设置下的外观，需要渲染证据或针对性的手动检查。
